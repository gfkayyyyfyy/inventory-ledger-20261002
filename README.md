# 小型仓储库存台账

建设面向小型仓库的本地库存管理产品，逐步覆盖商品与 SKU、库位、入库出库、库存调整、盘点差异、操作流水、低库存清单和 CSV 交换。

计划采用：Python 3 标准库 / sqlite3 / csv / argparse。

当前已实现：单仓库、整数数量的本地库存台账，无需第三方包或联网。库位、盘点、调整及 CSV 交换暂不在范围内。

## 使用方式

通过 `python -m inventory --db 文件路径` 访问台账。数据库父目录需事先存在；指定文件不存在时自动建立台账，后续命令使用同一路径读写，数据持久保存。

```bash
# 登记商品（初始数量为零）
python -m inventory --db ./ledger.db add --sku DEMO-1 --name 演示螺母

# 入库 / 出库
python -m inventory --db ./ledger.db receive --sku DEMO-1 --qty 10
python -m inventory --db ./ledger.db issue   --sku DEMO-1 --qty 3

# 查询商品名称、当前数量与完整流水
python -m inventory --db ./ledger.db show --sku DEMO-1

# 只查看编号严格大于 2 的后续流水（可与 --type 同用，两个条件同时满足）
python -m inventory --db ./ledger.db show --sku DEMO-1 --after-id 2
python -m inventory --db ./ledger.db show --sku DEMO-1 --after-id 2 --type receive

# 只查看编号严格小于 4 的早先流水（上界无需真实存在，也无需属于当前 SKU）
python -m inventory --db ./ledger.db show --sku DEMO-1 --before-id 4
# 上下界与类型、条数同用时取所有条件的交集，再按原始 id 升序截断
python -m inventory --db ./ledger.db show --sku DEMO-1 \
  --after-id 0 --before-id 4 --type receive --limit 2

# 限定一次最多返回 1 条流水；配合 --after-id 用上一条返回的编号继续查询
python -m inventory --db ./ledger.db show --sku DEMO-1 --type receive --limit 1
python -m inventory --db ./ledger.db show --sku DEMO-1 --type receive --limit 1 --after-id 1

# 低库存清单：返回当前数量小于或等于阈值的全部商品（无需指定 SKU）
python -m inventory --db ./ledger.db low-stock --threshold 5

# 同一份低库存清单也可导出为 CSV（UTF-8 无 BOM、LF 结束、首行 sku,name,quantity）
python -m inventory --db ./ledger.db low-stock --threshold 5 --format csv
```

`--after-id` 接受 0 至 9223372036854775807 的十进制非负整数（允许前导零），0 表示从最早流水开始；下界不要求实际存在，也不要求属于当前 SKU。完整参数值参与校验，不做去空白：含空格、制表符、回车、换行（无论在开头、结尾还是中间，包括数字后附单个换行）一律拒绝。筛选不改变商品当前数量，返回的流水保留原始编号、数量与余额，不重新编号或重算余额。

`--before-id` 接受 0 至 9223372036854775807 的十进制非负整数（允许前导零），数字文本沿用 `--after-id` 的语义：十进制数字字符按 Unicode 十进制语义识别（ASCII 数字、全角数字、阿拉伯印度数字等），不同文字的数字可混写，前导零（含数千位前导零）不改变数值。指定时仅返回原始 id 严格小于该值的该商品流水；上界无需对应实际流水，也无需属于当前 SKU；`--before-id 0` 合法并成功返回空 movements。与 `--after-id`、`--type` 同用时取所有条件的交集，再按原始 id 升序应用 `--limit`，其他商品的流水不占名额；下界大于或等于上界时成功返回空数组。完整参数值参与校验，不做去空白：参数缺值、空字符串、含任意空白（空格、制表符、回车、换行，无论在开头、结尾还是中间）、正负号、小数点、下划线、其他非十进制数字字符或数值越界时，统一以退出码 2 拒绝，标准输出为空，标准错误包含 `--before-id` 与拒绝原因，不出现异常堆栈。校验发生在访问数据库之前：不创建尚不存在的数据库文件，也不改变已有数据；上界错误先于空 SKU、不存在的 SKU 或不可用数据库路径报告。省略 `--before-id` 时保持原有查询语义。上界合法时，空 SKU 或不存在的 SKU 仍以退出码 2 拒绝，数据库无法打开或读取仍以退出码 1 拒绝。上界只用于本次查询，不保存。

`low-stock --threshold N` 按统一阈值查看低库存商品：必填的 `--threshold` 接受 0 至 9223372036854775807 的十进制非负整数，数字文本沿用 `--after-id` 的语义（Unicode 十进制数字字符，各文字数字可混写，前导零不改变数值），完整值含空白、正负号、小数点或其他非数字字符，以及参数省略、缺值、空字符串、数值越界时均以退出码 2 拒绝且不访问数据库。成功时标准输出为 `{"products": [...]}`，每项只含 `sku`、`name`、`quantity`（精确整数，不带流水），按 SKU 的 Unicode 字符顺序升序排列并区分大小写，与登记顺序无关；阈值 0 只匹配当前数量为零的商品。没有流水的已登记商品也参与判断；台账中没有商品或没有匹配项时成功返回 `{"products":[]}`。文件尚不存在且父目录存在时，沿用建立空台账的约定并返回空数组。查询为只读：不改变商品及流水，不保存阈值，数据不变时重复结果一致。

可选的 `low-stock --format F` 只改变该查询的输出格式，不改变商品集合：取值大小写敏感，只接受 `json` 或 `csv`；省略或指定 `json` 时输出与上面完全一致的单个 JSON 对象（字段、排序、阈值判断与退出码不变）。指定 `csv` 时把同一阈值下的同一批商品写入标准输出：无 BOM 的 UTF-8，记录以 LF 结束，首行固定为 `sku,name,quantity`，其后每个商品一条逻辑记录，顺序与 JSON 相同（区分大小写的 SKU 字符顺序）；SKU 与名称保留查询返回的原始文本，字段含逗号、双引号、回车或换行时用双引号包裹、内部双引号写成两个双引号，字段内部的回车与换行保持原样；数量写为精确的 ASCII 十进制整数，不带分组符或指数；没有匹配商品时只输出表头。成功时退出码 0、标准错误为空。`--format` 缺值、空字符串、其他取值、大小写变体（如 `CSV`、`Json`）或带两端空白均以退出码 2 拒绝，标准输出为空，标准错误包含 `--format` 与原因且无异常堆栈；格式校验与阈值一样发生在访问数据库之前，不创建尚不存在的台账、不改变已有数据。格式与阈值合法但数据库无法打开或读取时退出码 1、标准输出为空、原因写入标准错误。格式只用于本次输出，不保存，也不新增文件路径参数；`add`、`receive`、`issue`、`show` 不接受 `--format`，行为保持不变。

`--limit` 接受 1 至 1000 的十进制正整数（只允许 ASCII 数字 0 至 9，允许前导零，`0002` 与 `2` 等价）；完整参数值必须是非空的数字文本，不做去空白或数字字符转换：含空格、制表符、回车、换行（无论在开头、结尾还是中间）一律拒绝，全角数字（如 `２`）、阿拉伯印度数字（如 `٢`）及其与 ASCII 数字的混写也一律拒绝。省略时返回全部匹配流水。传入 N 时，先按 `--sku`、`--type`、`--after-id` 筛选，再按原始 id 升序取前 N 条，其他商品的流水不占名额。限制只影响 `movements`：商品名称与 `quantity` 仍表示当前状态，各流水保留原始编号、数量和余额，不重新编号或重算余额。匹配条数少于 N 时全部返回。翻页时沿用上一次的筛选参数并加入上一页最后一条流水的编号作为 `--after-id` 即可继续查询。

### 输出约定

- 成功：退出码 0，标准输出默认为单个 JSON 对象（`low-stock --format csv` 时为 CSV 文本，见下文）。
  - `add`/`receive`/`issue`：`{"sku", "name", "quantity"}`
  - `show`：额外包含 `movements` 数组，按流水编号升序；流水对象为 `{"id", "type", "quantity", "balance"}`，无流水时为 `[]`。
  - `low-stock`：`{"products": [...]}`，数组每项为 `{"sku", "name", "quantity"}`（精确整数，不带流水），按 SKU 的 Unicode 字符顺序升序排列并区分大小写；无商品或无匹配项时为 `[]`。指定 `--format csv` 时改为 CSV 文本（UTF-8 无 BOM、LF 结束）：首行固定 `sku,name,quantity`，其后每个商品一条记录、顺序与 JSON 相同；字段含逗号、双引号、回车或换行时按双引号规则包裹且内部双引号翻倍，字段内部回车/换行保持原样，数量为精确 ASCII 十进制整数；无匹配商品时只输出表头。
  - `show` 可用 `--type`（`receive`/`issue`）按类型筛选，用 `--after-id ID` 只返回编号严格大于 ID 的流水，用 `--before-id ID` 只返回编号严格小于 ID 的流水；三者可同时使用，返回同时满足全部条件的流水。无匹配（含 `--before-id 0`、下界大于或等于上界）时退出码仍为 0、`movements` 为 `[]`，商品当前数量照常返回。
  - `show` 可用 `--limit N` 在 `--sku`/`--type`/`--after-id`/`--before-id` 筛选之后按原始 id 升序取前 N 条流水；省略 `--limit` 时返回全部匹配流水，匹配条数少于 N 时全部返回。限制只影响 `movements`，商品名称与当前数量不变，流水保留原始编号、数量和余额，不重新编号或重算余额。
- 参数或业务错误（空 SKU/名称、重复登记、商品不存在、无效数量、单次数量超过上限、入库后余额超过上限、出库超过余额、非法 `--after-id`/`--before-id`/`--type`/`--limit`/`--threshold`）：退出码 2，原因写入标准错误，标准输出为空，数据不改变。
  - `--qty` 接受 1 至 9223372036854775807 的十进制正整数（允许前导零，前导零不改变数量含义）；十进制数字包括 ASCII 数字以及全角数字（如 `２`，U+FF12）、阿拉伯印度数字（如 `٣`，U+0662）等各文字的 Unicode 十进制数字字符，不同文字的数字可混写（如 `2０٣` 等于 203）。零、负数、小数、非数字按数量无效拒绝：纯十进制数字文本只要实际数值为零即拒绝，零字符可以是 `0`、`000`、全角 `０`、阿拉伯印度 `٠` 或其混写（如 `0０٠`），也可以是数千位的长文本。超过上限时错误信息包含 `--qty` 与允许的上限。即使本次数量自身合法，只要当前余额加上本次入库数量超过 9223372036854775807，也按业务错误拒绝，错误信息说明库存上限、当前余额和本次数量；不改变余额、商品名称或已有流水，也不新增流水。数量非法（含超过单次上限）且 SKU 不存在时，先按数量错误拒绝。
  - `--after-id` 缺值、空字符串、含空格/制表符/回车/换行（无论在开头、结尾还是中间，含数字后附单个换行）、负数、小数、正号、非数字或超出 0–9223372036854775807 范围时按参数错误拒绝（退出码 2、标准输出为空，标准错误包含 `--after-id` 与拒绝原因，不出现异常堆栈），已有商品和流水不变，也不创建尚不存在的数据库文件；非法 `--after-id` 与 SKU 为空或不存在、合法的 `--type`/`--limit` 同时出现时先报告参数错误。
  - `--before-id` 缺值、空字符串、含任意空白（空格/制表符/回车/换行，无论在开头、结尾还是中间）、正负号、小数点、下划线、其他非十进制数字字符或超出 0–9223372036854775807 范围时按参数错误拒绝（退出码 2、标准输出为空，标准错误包含 `--before-id` 与拒绝原因，不出现异常堆栈），已有商品和流水不变，也不创建尚不存在的数据库文件；非法 `--before-id` 与 SKU 为空或不存在、合法的 `--after-id`/`--type`/`--limit` 同时出现时先报告参数错误。上界合法但 SKU 为空或不存在时，仍按商品错误拒绝（退出码 2）；数据库无法打开或读取仍以退出码 1 拒绝。
  - `--limit` 缺值、空字符串、零、负数、小数、正号、非 ASCII 数字（全角数字、阿拉伯印度数字及其混写）、含空格/制表符/回车/换行（无论在开头、结尾还是中间）、其他非数字或超过 1000 时按参数错误拒绝（退出码 2、标准输出为空，标准错误包含 `--limit` 与拒绝原因，不出现异常堆栈），已有商品和流水不变，也不创建尚不存在的数据库文件；非法 `--limit` 与不存在的 SKU 同时出现时先报告参数错误。参数合法但 SKU 为空或不存在时，仍按商品不存在拒绝（退出码 2、标准输出为空，标准错误说明 SKU 为空或商品不存在）。
  - `low-stock --threshold` 为必填：参数省略、缺值（`--threshold` 后无值）、空字符串、含空格/制表符/回车/换行（无论在开头、结尾还是中间）、正负号、小数点、下划线、其他非数字字符或数值超出 0–9223372036854775807 范围时按参数错误拒绝（退出码 2、标准输出为空，标准错误包含 `--threshold` 与拒绝原因，不出现异常堆栈）。阈值在打开数据库之前校验，已有商品和流水不变，也不创建尚不存在的数据库文件。阈值只用于本次查询，不保存为商品或台账设置。
  - `low-stock --format` 为可选，缺省 `json`；只接受大小写敏感的 `json` 或 `csv`。缺值、空字符串、其他取值、大小写变体（`CSV`、`Json`、`JSON` 等）或带两端空白（空格、制表符、回车、换行）时按参数错误拒绝（退出码 2、标准输出为空，标准错误包含 `--format` 与拒绝原因，不出现异常堆栈）。格式在打开数据库之前校验，已有商品和流水不变，也不创建尚不存在的数据库文件；格式只用于本次查询，不保存。该参数仅 `low-stock` 接受，`add`/`receive`/`issue`/`show` 的行为不受影响。
- 数据库无法打开或读写：退出码 1，原因写入标准错误。

### 业务规则

- SKU 与名称去掉两端空白后不能为空；所有命令按去空白后的 SKU 精确查找，SKU 区分大小写。
- 数量只接受 1 至 9223372036854775807（2^63-1）的十进制正整数（拒绝零、负数、小数、非数字），允许前导零且不改变数量含义；十进制数字按 Unicode 数值识别，ASCII、全角、阿拉伯印度等各文字的数字字符与其混写按同一数值处理，纯数字文本只要实际数值为零（`0`、`000`、`０`、`٠`、`0０٠` 等）一律拒绝。库存余额限定在 0 至 9223372036854775807：入库后余额恰好等于上限允许成功，超过上限即使本次数量合法也按业务错误拒绝；出库数量等于余额时允许成功，余额变为零。所有数量与余额在 JSON 中均为精确整数（不会变为小数、指数近似值或字符串）。
- 每次入库/出库新增一条流水，记录唯一递增编号、类型（`receive`/`issue`）、本次正整数数量和操作后余额；余额更新与流水写入在同一事务内同时生效或同时不生效，任何拒绝都不新增流水。登记和查询不产生流水。
- `show --after-id ID` 按流水编号查看后续记录：仅返回该 SKU 中 `id > ID` 的流水，编号升序排列，与 `--type` 同用时取交集；筛选只影响返回的行，商品的 `sku`、`name`、`quantity` 以及各流水的原始编号、数量、余额均不变。
- `show --before-id ID` 按流水编号查看早先记录：仅返回该 SKU 中 `id < ID` 的流水，上界不要求实际存在，也不要求属于当前 SKU；`--before-id 0` 合法并返回空数组。与 `--after-id`、`--type` 同用时取所有条件的交集；下界大于或等于上界时结果为空。筛选只影响返回的行，商品的 `sku`、`name`、`quantity` 以及各流水的原始编号、数量、余额均不变。
- `show --limit N` 在 `--sku`、`--type`、`--after-id`、`--before-id` 筛选后按原始 id 升序只返回前 N 条流水；名额只在该 SKU 已筛选的流水内计数，其他商品的流水不占名额。限制只影响 `movements`，不改变商品当前数量，也不重新编号或重算余额；省略时返回全部匹配流水。查询不写入数据库，重复查询结果一致。
- `low-stock --threshold N` 返回当前数量小于或等于 N 的全部已登记商品（含没有流水、数量为零的商品），不需要也不接受 SKU；结果只含 `sku`、`name`、`quantity`，按 SKU 的 Unicode 字符顺序升序排列并区分大小写（SQLite TEXT 二进制排序），与登记顺序无关。阈值仅用于本次查询、不保存；查询只读，重复结果一致。可选的 `--format csv` 只把同一结果集改写为 CSV 输出（UTF-8 无 BOM、LF 结束、首行 `sku,name,quantity`、无匹配时只输出表头），不改变商品集合、排序或任何数据。
- 不同数据库文件的数据各自独立。

## 运行测试

出入库数量与库存余额边界的回归测试位于 `tests/`，仅使用 Python 标准库，每个用例使用独立临时数据库，可重复执行。

```bash
python -m unittest discover
```

全部通过时输出 `OK`（如环境只有 `python3`，相应替换命令名）。
